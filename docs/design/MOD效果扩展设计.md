# SourceForge MOD 效果扩展设计（第一批：48 张）

> 状态：**仅设计，不改配置、不写实现、不加入掉落池。**  
> 基线：2026-07-18，已核对当前启用的 52 张 MOD（不含测试卡）。  
> 目标：补足战术、信息、资源调度、协作、召唤指挥和探索工具的玩法空白，而不是再做一张“换条件的加伤卡”。

## 1. 本批的去重规则

“不重复”按**玩家实际获得的主要能力**判断，而不是只看配置键名：

- 不新增固定 `base_damage`、暴击率、暴伤、处决增伤、易伤、攻速、元素伤害、元素触发率、吸血或反伤。
- 不新增生命、护甲、护盾容量、移速、能量上限、技能强度、效率、持续、范围等常驻数值卡。
- 不新增前冲、后撤、跳跃砸地、扇形斩、散射弹幕、溅射弹、单次格挡、持续减伤、静止回血、掉落翻倍、连锁挖矿、召唤物数量或伤害。
- 少数卡会改变“投射物如何到达目标”或“队友如何协作”，但**不会改变原技能/武器的伤害数值、元素层数或触发概率**。

| 现有覆盖面 | 已有代表 MOD | 本批避开的重复方向 |
| --- | --- | --- |
| 常驻攻击属性 | `serration`、`critical_strike`、`savage_blow`、`execution`、`soulmark` | 一切固定增伤、暴击、斩杀、易伤卡 |
| 元素与异常 | `hellfire`、`frostbite`、`venom`、`shock`、`miasma_core`、`phase_catalyst` | 新元素、DOT、元素层数、异常概率或组合增幅 |
| 资源与技能属性 | `flow`、`streamline`、`intensify`、`continuity`、`stretch`、`blind_rage` | 能量上限、常驻减耗、技能强度/范围/持续 |
| 生存 | `vitality`、`steel_fiber`、`redirection`、`siphon_rounds`、`thorned_retribution`、`parry`、`iron_stance`、`hearth_whisper` | 常驻生命/护甲/盾、吸血、反伤、单次格挡、持续减伤、回血光环 |
| 位移与近战招式 | `dash_thrust`、`wind_retreat`、`skill_leap`、`blood_mist_onslaught`、`ground_slam`、`crescent_slash`、`triple_slash` | 再做一张冲刺、撤退、跳砸、扇形斩或连段斩 |
| 远程与采集 | `frag_rounds`、`overcharge_shot`、`suppression_barrage`、`desecrate`、`chain_mining`、`obsidian_blast` | 溅射、蓄力重弹、散射、掉落翻倍、自动挖矿、秒破黑曜石 |
| 召唤 | `summon_aery`、`summon_might`、`legion_banner` | 召唤物伤害、数量上限、额外攻击型精灵 |

## 2. 通用数值约定

- 除特别说明外，所有卡均建议 `max-rank: 4`，即 5 段；下文的区间为 1 段 → 5 段。
- 主动技能的冷却、能量成本遵守现有数值文档：常规功能技能 8–16 能量、控制/保命技能 16–30 能量、冷却 8–30 秒。
- 所有影响生物行为的效果默认只作用于怪物；PVP、Boss、不可移动实体必须有独立开关或衰减规则。
- `实现层` 仅用于排期，不代表当前已经支持：`E` = 事件监听扩展，`S` = 技能脚本加少量 API，`W` = 世界/背包/导航等独立子系统。

## 9. 推荐分批上线顺序

第一批不建议把 48 张一次性塞进抽奖池。每批 8–12 张，先验证服务器性能、Boss 兼容和队伍体验：

1. **低风险功能卡**：`hunter_lens`、`recovery_line`、`kinetic_capacitor`、`bounty_reactor`、`distress_beacon`、`ore_echo`、`vein_survey`、`salvage_magnet`。
2. **战术主动卡**：`tether_hook`、`anchor_exchange`、`gravity_well`、`smoke_lattice`、`mirror_decoy`、`prism_wall`、`silence_pulse`、`rescue_blink`。
3. **需要状态机/实体管理的卡**：`cooldown_archive`、`failsafe_protocol`、`adaptive_plating`、`guardian_link`、`rift_mine`、`summon_orders`、`formation_recall`。
4. **需要独立子系统的卡**：`vector_gate`、`watcher_orb`、`relay_totem`、`salvage_drone`、`compact_field`、`mod_insurance`、`hazard_compass`、`cache_seal`、`field_reconfigurator`。

## 10. 下一步评审口径

进入实现前，每张卡至少过以下检查：

1. **唯一性**：能否用一张现有 MOD 的现有主要效果描述它？能，就淘汰或重做。
2. **可读性**：玩家能否在一行 lore 中理解“什么时候触发、发生什么、有什么限制”？
3. **反滥用**：是否能刷能量、穿墙、无限保命、绕过锻炉或复制物品？能，就先写硬限制。
4. **Boss/PVP**：拉扯、静默、诱饵、换位、救援是否有 Boss 衰减与 PVP 开关？
5. **性能**：扫描、追踪、掉落物流、召唤物都必须限半径、限频率、限数量，并在卸装/离线时清理状态。

这份设计刻意保留了“伤害数值”空位：若后续要增加输出型卡，应先在本稿的非伤害机制稳定后，再单独做第二批，并为每张输出卡写明它不会与现有的基础伤害、暴击、元素、易伤、处决、连段或范围伤害重叠。
